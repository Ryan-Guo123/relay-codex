# Relay Artifact Protocol

Relay is a repo-local evidence layer. Its artifacts should be readable in GitHub, useful to future Codex runs, and easy for other tools to index without adopting a Relay server.

The protocol is intentionally small:

```text
.relay/
  mission.md
  state.md
  queue.md
  guardrails.md
  automations.md
  events.jsonl
  handoff.md
  review-readiness.md
  pr-comment.md
  reviewer-pack.md
  validation-brief.md
  release-checklist.md
```

## Design Rules

- Human-readable first: Markdown is the source of truth for maintainer handoff.
- Repo-local by default: artifacts live beside the code and can be reviewed in diffs.
- Evidence, not memory: Relay stores maintainer state, not broad personal or project memory.
- Generated files may be overwritten by Relay commands; human-authored notes should be kept in the documented editable sections.
- No secrets: Relay artifacts should not contain credentials, private customer data, tokens, or sensitive operational context.

## Required Artifacts

These files are created by `relay_runtime.py enable`.

### `.relay/mission.md`

Purpose:

- Capture the project goal Relay should preserve across Codex runs.
- Give future maintainers and agents the success definition before they continue.

Ownership:

- Generated by Relay on first enable.
- Maintainer-editable after creation.

Required headings:

- `# Relay Mission`
- `## Success Definition`
- `## Observed Context`
- `## Human Notes`

Indexing guidance:

- Index the project name, inferred stack, success definition, and human notes.
- Treat `Human Notes` as maintainer-authored context, not verified runtime evidence.

### `.relay/state.md`

Purpose:

- Record the current Relay verdict and the signals behind it.

Ownership:

- Generated and refreshed by Relay during inspect, handoff, release, and recovery commands.
- Do not treat manual edits as durable; they may be overwritten.

Required headings:

- `# Relay State`
- `## Recent Progress`
- `## Current Signals`

Required fields:

- `Verdict`
- `Phase`
- `Last refreshed`

Allowed verdicts:

- `continue`: next task is clear and recent events show forward motion.
- `paused`: queue is empty or the repo should not continue automatically.
- `needs_human`: missing product, credential, approval, or scope input blocks progress.
- `needs_review`: churn, repeated failure, or likely drift should be inspected before continuing.

Indexing guidance:

- Index verdict, phase, last refreshed timestamp, recent progress, and current signals.
- Use this file to decide whether another agent run should continue or stop.

### `.relay/queue.md`

Purpose:

- Keep the next work visible and reviewable.
- Make recovery tasks explicit when the repo is stuck.

Ownership:

- Generated by Relay during enable, inspect, and recover.
- Maintainer-editable, but subsequent inspect/recover commands may refresh it.

Required headings:

- `# Relay Queue`
- `## Next Tasks` for normal queues
- `## Why Relay Chose This` for normal queues
- `## Recovery Tasks` for recovery queues
- `## Recovery Trigger` for recovery queues

Required fields:

- `Current verdict`
- Markdown task list items using `- [ ]`

Indexing guidance:

- Index unchecked tasks and current verdict.
- Treat recovery queues as a stronger stop signal than normal queues.

### `.relay/guardrails.md`

Purpose:

- Explain when Relay should stop, ask for help, or switch to recovery.

Ownership:

- Generated by Relay on first enable.
- Maintainer-editable after creation.

Required headings:

- `# Relay Guardrails`
- `## Escalation Rules`

Indexing guidance:

- Index escalation rules and stop conditions.
- Use as policy context for future agent runs.

### `.relay/automations.md`

Purpose:

- Describe suggested follow-up automation packs.

Ownership:

- Generated by Relay on first enable and refreshed by the automations command.

Required headings:

- `# Relay Automation Packs`
- One `##` heading per automation pack.

Current pack names:

- `Continue Working`
- `Daily Triage`
- `Stuck Recovery`
- `Release Readiness`

Indexing guidance:

- Index pack names, purposes, cadences, and triggers.
- Do not treat suggested automation packs as proof that an automation is installed.

### `.relay/events.jsonl`

Purpose:

- Preserve a lightweight event log from Codex tool activity and Relay recovery events.

Ownership:

- Appended by Relay hooks and recovery commands.
- Should not be hand-edited except to remove sensitive information before sharing.

Format:

Each line is a JSON object. Known fields include:

```json
{
  "timestamp": "2026-05-31T00:00:00+00:00",
  "kind": "write",
  "summary": "Updated the dashboard empty state copy."
}
```

Known event kinds:

- `write`, `edit`, `multi_edit`: substantive file changes.
- `bash`: shell command activity.
- `recovery_brief`: Relay generated a recovery queue.
- `invalid_event`: Relay preserved a malformed event line as text.

Indexing guidance:

- Index timestamp, kind, and summary.
- Keep only lightweight summaries. Do not use `events.jsonl` as a full transcript store.

## Generated Handoff Artifacts

These files are generated on demand after the base workspace exists.

### `.relay/handoff.md`

Command:

```bash
python3 plugins/relay-codex/scripts/relay_runtime.py handoff
```

Purpose:

- Turn current Relay state into a maintainer-ready PR, review, or future-run handoff.

Ownership:

- Generated by Relay and overwritten on each handoff command.

Required headings:

- `# Relay Handoff`
- `## Maintainer Summary`
- `## Last Successful Signal`
- `## Current Signals`
- `## Recent Events`
- `## Queue Snapshot`
- `## Recommended Next Action`
- `## Review Focus`
- `## Safe Handoff Rules`

Indexing guidance:

- Index verdict, last successful signal, recommended next action, and review focus.
- This is the best single file for a future maintainer or agent to read before continuing.

### `.relay/review-readiness.md`

Command:

```bash
python3 plugins/relay-codex/scripts/relay_runtime.py review-readiness
```

For clean PR checkouts, pass `--base-ref origin/main` or another fetched base ref so Relay reads committed branch changes instead of `git status`.

Purpose:

- Turn current changed-file scope, sensitive-path matches, and CODEOWNERS routing into a standalone review gate.
- Let maintainers or CI-like workflows inspect review risk without generating a full PR comment.

Ownership:

- Generated by Relay and overwritten on each review-readiness command.
- Must not be treated as merge approval; it is a routing and review-prep artifact.

Required headings:

- `# Relay Review Readiness`
- `## Review Gate`
- `## Suggested Reviewers`
- `## Current Relay Signals`
- `## Recommended Review Decision`
- `## Safe Use`

Indexing guidance:

- Index changed-file count, `base_ref`, `change_source`, large-scope warning, sensitive paths, CODEOWNERS-suggested reviewers, unowned paths, and structured `decision` fields: `risk_level`, `decision`, and `recommended_action`.
- Treat this as the smallest machine-readable review gate; read `pr-comment.md` when a GitHub-ready narrative is needed.

Machine-readable JSON:

- `review-readiness --json` emits the structured payload used by GitHub Actions artifacts.
- The JSON compatibility contract is documented in [review-readiness.schema.json](review-readiness.schema.json).
- Consumers should tolerate additional top-level fields and should rely only on the documented `review_readiness` fields for routing decisions.

### `.relay/pr-comment.md`

Command:

```bash
python3 plugins/relay-codex/scripts/relay_runtime.py pr-comment
```

For clean PR checkouts, pass `--base-ref origin/main` to make the `What Changed` and `Review Readiness` sections use committed branch diff instead of `git status`.

Purpose:

- Turn the current Relay handoff into a GitHub-ready PR comment draft.
- Preserve verdict, changed files, review-readiness signals, CODEOWNERS routing hints, verification evidence, risks, recent events, and next action in a pasteable format.

Ownership:

- Generated by Relay and overwritten on each PR comment command.
- Must not be posted to GitHub automatically; a maintainer reviews and redacts it first.

Required headings:

- `## Relay PR Handoff`
- `### Current State`
- `### What Changed`
- `### Review Readiness`
- `### Last Successful Signal`
- `### Verification`
- `### Risks / Review Focus`
- `### Recent Relay Events`
- `### Recommended Next Action`
- `### Maintainer Checklist`

Indexing guidance:

- Index verdict, review posture, changed files, sensitive-path warnings, large-scope warnings, CODEOWNERS-suggested reviewers, verification evidence, risks, and recommended next action.
- Treat this as a PR surface, not a complete project memory or merge approval.

### `.relay/reviewer-pack.md`

Command:

```bash
python3 plugins/relay-codex/scripts/relay_runtime.py reviewer-pack
```

Purpose:

- Package `.relay/pr-comment.md` into an outside-review request.
- Include the reviewer prompt, comparison placeholder, review-readiness rubric, outcome choices, and feedback recording instructions.

Ownership:

- Generated by Relay and overwritten on each reviewer-pack command.
- Must not be treated as validation by itself; it is only a packet to send after maintainer review and redaction.

Required headings:

- `# Relay Reviewer Pack`
- `## Reviewer Ask`
- `## Relay Handoff To Review`
- `## Compare Against`
- `## Scoring Rubric`
- `## Required Outcome`
- `## Record The Feedback`

Indexing guidance:

- Index reviewer outcome choices and rubric fields.
- Treat this as a validation request artifact, not a product success signal.

### `.relay/validation-brief.md`

Command:

```bash
python3 plugins/relay-codex/scripts/relay_runtime.py validation-brief
```

For clean PR checkouts, pass `--base-ref origin/main` so the embedded review-readiness gate reflects the committed PR diff.

Purpose:

- Package `.relay/reviewer-pack.md` into a shareable outside-validation ask.
- Make the required reviewer outcome and validation-ledger update explicit.
- Keep the public ask focused on evidence, not stars, praise, or sponsorship.

Ownership:

- Generated by Relay and overwritten on each validation-brief command.
- Must not be treated as validation by itself; only an outside reviewer outcome counts.

Required headings:

- `# Relay Validation Brief`
- `## Validation Goal`
- `## Artifacts To Share`
- `## Current Review Gate`
- `## Short Ask`
- `## Reviewer Pack`
- `## Feedback To Record`
- `## Guardrails`

Indexing guidance:

- Index the validation goal, artifacts to share, review gate, required outcomes, and guardrails.
- Treat this as the best single file to send before asking an outside maintainer for feedback.

### `.relay/release-checklist.md`

Command:

```bash
python3 plugins/relay-codex/scripts/relay_runtime.py release
```

Purpose:

- Turn current Relay state into a release-readiness checklist.

Ownership:

- Generated by Relay and overwritten on each release command.

Required headings:

- `# Relay Release Checklist`
- `## Release Posture`
- `## 1. Scope`
- `## 2. Verification`
- `## 3. Version And Tag`
- `## 4. Release Notes`
- `## 5. Human Approval Gates`
- `## 6. After Release`

Indexing guidance:

- Index release posture, verification commands, human approval gates, and post-release tasks.
- Do not use this file as approval. It records gates; a maintainer still approves the release.

## Integration Guidance

Agent boards, memory tools, and future dashboards should treat `.relay/` as a handoff artifact set:

- Read `state.md` first for the current verdict.
- Read `handoff.md` before continuing or reviewing work.
- Read `review-readiness.md` before deciding whether a PR is scoped and routed for review.
- Read `pr-comment.md` before posting a GitHub PR update.
- Read `reviewer-pack.md` before asking an outside maintainer for feedback.
- Read `validation-brief.md` when collecting measurable outside-review evidence.
- Read `release-checklist.md` before tagging or publishing a release.
- Read `events.jsonl` for recent lightweight evidence.
- Do not infer broad project memory from Relay artifacts alone.

Relay artifacts can be indexed by other systems, but Relay itself should stay repo-local and serverless until the validation plan proves a stronger need.

## Compatibility Contract

Relay can add new fields and sections without a major version change.

`docs/review-readiness.schema.json` is the public schema for the current `review-readiness --json` payload. It is intended for GitHub Actions, dashboards, memory tools, and other integrations that want to validate Relay output without parsing Markdown.

Relay should avoid removing or renaming these stable headings without a documented migration:

- `# Relay State`
- `# Relay Queue`
- `# Relay Handoff`
- `## Relay PR Handoff`
- `# Relay Reviewer Pack`
- `# Relay Validation Brief`
- `# Relay Release Checklist`
- `## Current Signals`
- `## Recommended Next Action`
- `## Human Approval Gates`

If a future version changes verdict names or required files, it should update this protocol and the runtime tests in the same PR.
